## Fin Track

This package is the web client of Fin Track, a Spanish personal-finance app. The product overview and the Compose setup live in the parent directory's `README.md` and `AGENTS.md`.

Pages under the dashboard layout share the `Section` component as their `main`, so the gap and the horizontal padding stay the same. `Section` accepts an optional `actions` slot on the same row as the title. Categorías uses it for the Todo / Egresos / Ingresos tabs, Estadísticas for the period tabs, and Movimientos for Importar, Exportar and Nuevo. Routes: `/login`, `/dashboard` (Resumen), `/dashboard/movimientos`, `/dashboard/categorias`, `/dashboard/estadisticas` and `/dashboard/configuracion`. Desktop navigation (`xl`) lists all five. Below `xl`, the bottom bar lists the first four plus the create button; Configuración is a session-menu item. History uses one shared `MovementList`. From `sm` up the row is icon, category, type, date, amount, edit and delete. Below `sm` it is icon, type, amount and a three-dot menu (Ver, Editar, Eliminar); Ver opens a detail sheet with category and date. Movimientos adds search, a type switch and a category select inside the history card. Importar opens a dialog next to Exportar. It downloads `GET /api/finanzas/importar/plantilla` and posts the completed `.xlsx` to `POST /api/finanzas/importar`, which proxies `GET /transacciones/importar/plantilla` and `POST /transacciones/importar`. The dialog lists `errores` and does not close when the file is rejected. A successful import calls `refresh`. Exportar asks `GET /api/finanzas/exportar/:formato` (`csv`, `excel` or `pdf`), which proxies `GET /transacciones/exportar/:formato` and downloads the attachment. The file is every movement through today, not the filtered rows. The registration dialog is titled "Nuevo movimiento" when creating and "Editar movimiento" when editing; it is a bottom sheet on small screens and a centered modal from `sm` up. Selects use `bg-background` like the modal. The default currency is the display currency from `fin-track-preferencias`. Category is a `<select>` of existing categories for the chosen type plus `Sin categoría` (default). The icon picker shows only when `Sin categoría` is selected; otherwise the chosen category's icon is used. Resumen shows at most five movements and a link to Movimientos. `Chatbot`, mounted in `AppShell`, sits at the bottom-right (above the bottom bar below `xl`). Below `sm`, the open panel is full-viewport (`fixed inset-0`, safe-area insets) and the floating toggle is hidden while open; from `sm` up it stays a compact card next to the button. It posts the last eight messages to `POST /api/asistente/chat`, which proxies `POST /asistente/chat`. Assistant bubbles render markdown with `react-markdown` and `remark-gfm` (lists, tables, emphasis, code). User bubbles stay plain text. Images are omitted and links open in a new tab. A `{ fallback: true }` body, a non-OK response other than 401 and 429, or a network error answers from `GET /api/finanzas` for the current or previous month. 401 sends the user to `/login`. 429 shows the busy message.

The app is an installable PWA without offline finance data. `src/app/manifest.ts` serves `/manifest.webmanifest` (`display: standalone`, `start_url: /`, icons under `public/`). `ServiceWorkerRegister` in the root layout registers `/sw.js` with `updateViaCache: "none"`. The worker precaches the manifest and icons only; it never caches `/api/*` or HTML navigation. Install works over HTTPS (ngrok) or localhost; iOS uses `appleWebApp` and `/apple-touch-icon.png`.

`LoadingScreen` (`src/components/loading-screen.tsx`) uses `Spinner` (`src/components/spinner.tsx`). They cover login and signup while the action is pending, dashboard Suspense and `dashboard/loading.tsx`, and the first fetch of Resumen, Movimientos, Categorías and Estadísticas. `NavigationLoading` in the root layout shows the same overlay when an internal link (or `beginRouteLoading` before `router.push`) changes the route.

Each React component lives in its own file under `src/components/` (SVG icons under `src/components/icons/`). Shared non-component helpers stay in `*-data`, `*-types`, `*-styles` or `use-*.ts` modules next to them. Do not add a second component to an existing file.

The app font is JetBrains Mono, loaded with `next/font` and set on `body`. Cards and tables use the same gray as the period tabs (`bg-neutral-200/60`, `dark:bg-neutral-900`). Income category icons use an emerald border and icon.

Theme (localStorage key `theme`, values `light`, `dark` or `system`) and display currency (localStorage key `fin-track-preferencias`, only `{ moneda }`) are browser-only. A missing value follows the system color scheme, and `system` keeps following it while the page is open. The default display currency is ARS. API totals are USD. `format` converts them with `GET /api/finanzas/cotizaciones` (units of the display currency per 1 USD) and falls back to USD when that rate is missing. History rows, search and the assistant's movement lines use `formatMoneda(monto, moneda)`. Stats, the year summary and category totals sum `usd`. `DisplaySettingsProvider` wraps the shell and exposes `cambios` and `recargarCambios`.

The movement dialog defaults currency to the display preference and category to `Sin categoría`. For any non-USD currency without a stored rate it asks the admin for the rate, PUTs `/api/finanzas/cotizaciones/:moneda` with `{ valor }`, then posts the movement with `moneda`. A non-admin sees that an administrator must register the rate and the submit button stays disabled. `AppShell` receives `administrador` from `session.roles` (`GET /auth/me`) and exposes it with `useAdministrador`. Configuración lets every signed-in user change their own password through `PATCH /api/auth/contrasena` (`actual` and `nueva`; the confirmation is checked in the browser). It also lists every non-USD currency; only the admin can save a rate. When `administrador` is true, Configuración also shows `UsersAdminCard`: search, a users table and Ver / Editar / Eliminar. It loads `GET /api/usuarios` and `GET /api/roles`, patches roles with `PATCH /api/usuarios/:id`, and deletes with `DELETE /api/usuarios/:id`. Delete is disabled for the signed-in username; the API also refuses the bootstrap admin and users with finance rows. The session menu and the dialog both depend on that flag.

End-to-end tests use `@playwright/test` against Chromium. Specs live in `e2e/`, the config is `playwright.config.ts`, and `yarn test:e2e` runs them. `baseURL` is `http://localhost:3000`. Outside CI the runner reuses a server already on that port; otherwise it starts `yarn dev`. Install the browser with `yarn playwright install chromium`. Do not commit `test-results/`, `playwright-report/` or `blob-report/`.

Authentication is delegated to the Nest backend at `BACKEND_URL`. The browser never sees the password. `access_token` and `refresh_token` are httpOnly cookies. `/` redirects to `/login` in `next.config.ts`; do not call `redirect()` from `src/app/page.tsx` while `cacheComponents` is enabled. `allowedDevOrigins` and `experimental.serverActions.allowedOrigins` allow `*.ngrok-free.app`, `*.ngrok-free.dev`, `*.ngrok.app` and `*.ngrok.io` so the dev server and Server Actions accept the ngrok tunnel. The authtoken stays in the parent `.env.ngrok` as `NGROK_AUTHTOKEN`. A server component cannot persist a rotated refresh token, so an expired access token is recovered through `GET /api/auth/refresh`. The login screen can switch to Crear cuenta. That posts `POST /auth/signup`, which creates the `user` role, then signs in. Roles and permissions are enforced by the API. The admin Configuración screen manages other users through `/api/usuarios` and `/api/roles`. A common user can read and write their own finance records and cannot change exchange rates or manage users.
